HONOR OF KINGS GLOBAL — DRAFT, TIER LIST & SCRIM SIMULATOR
PROMPT COMPLET POUR CLAUDE

Je veux que tu développes un site web entièrement gratuit dédié à Honor of Kings Global.

L'objectif est de créer un véritable outil permettant de :

1. simuler des phases de Ban & Pick avec les règles de draft compétitives ;
2. consulter et filtrer l'ensemble des héros disponibles sur Honor of Kings Global ;
3. créer et gérer des Tier Lists personnalisées ;
4. simuler et enregistrer des scrims complets ;
5. simuler plusieurs Games dans une même série : BO1, BO2, BO3, BO4, BO5, BO7, etc. ;
6. conserver les compositions, bans, picks, résultats et durées de chaque Game ;
7. calculer ensuite des statistiques à partir des scrims réellement enregistrés.

Le site doit être fonctionnel, propre, moderne, responsive et réellement utilisable.

Je ne veux pas uniquement une maquette ou une démo statique.


==================================================
1. IMPORTANT : HONOR OF KINGS GLOBAL UNIQUEMENT
==================================================

Le jeu ciblé est :

Honor of Kings — Global version

Il ne faut PAS utiliser par défaut les données, héros ou images provenant exclusivement de la version chinoise :

王者荣耀 / Honor of Kings CN

Avant de développer la partie héros, recherche les sources permettant d'obtenir les données et images correspondant au roster Global actuel.

Je veux notamment :

- tous les héros disponibles sur la version Global ;
- leur nom ;
- leur ID si disponible ;
- leur image/portrait ;
- leur rôle/lane ;
- éventuellement leurs rôles secondaires ;
- leur disponibilité sur Global.

Les images doivent provenir d'une source fiable.

Si les assets officiels du site Honor of Kings Global sont accessibles publiquement, privilégie-les.

L'objectif est que le site puisse facilement être mis à jour lorsque de nouveaux héros arrivent sur Global.

Ne crée PAS manuellement une petite liste fictive de héros pour la démonstration.


==================================================
2. MISE À JOUR AUTOMATIQUE DU ROSTER
==================================================

C'est une exigence importante du projet.

La liste des héros ne doit PAS être considérée comme une liste statique qui devra être modifiée manuellement dans le code à chaque sortie d'un nouveau héros.

Je veux que le système puisse mettre automatiquement à jour le roster Honor of Kings Global.

Lorsqu'un nouveau héros devient disponible sur Honor of Kings Global, le site doit pouvoir récupérer automatiquement ses informations et l'ajouter au roster.

Il ne doit donc pas être nécessaire de modifier manuellement heroes.json ou un tableau TypeScript à chaque nouveau héros.


==================================================
3. SOURCE DES DONNÉES
==================================================

Lors de l'étape de recherche, vérifie :

1. où récupérer la liste actuelle des héros Honor of Kings Global ;
2. où récupérer leurs portraits/images ;
3. comment récupérer leurs lanes/rôles ;
4. si les assets officiels peuvent être utilisés directement ;
5. s'il existe une API publique ;
6. s'il existe une source open-source fiable ;
7. comment automatiser la mise à jour du roster ;
8. comment différencier proprement Global et CN.

Privilégie les sources officielles lorsque c'est possible.

Si les données officielles ne sont pas exposées sous forme d'API publique, recherche une solution permettant de récupérer automatiquement les données depuis les assets/données publiques du site officiel.

Une source communautaire fiable peut être utilisée comme fallback si aucune source officielle exploitable n'existe.

==================================================
6. GESTION DES NOUVEAUX HÉROS
==================================================

Lorsqu'un nouveau héros est détecté :

1. il est ajouté automatiquement au roster ;
2. son image est récupérée ;
3. ses informations sont ajoutées ;
4. il apparaît automatiquement dans la page Heroes ;
5. il apparaît automatiquement dans les filtres ;
6. il devient automatiquement disponible dans les futures Drafts ;
7. il apparaît dans la zone Unranked des nouvelles Tier Lists.

Aucune modification manuelle du code de la Draft ne doit être nécessaire pour ajouter un nouveau héros.


==================================================
7. GESTION DES HÉROS RETIRÉS OU MODIFIÉS
==================================================

Prévoir le cas où un héros :

- n'est plus disponible sur Global ;
- change de rôle ;
- change de lane ;
- change d'image ;
- reçoit des informations mises à jour.

Ne supprime pas brutalement un héros déjà présent dans une Tier List ou un ancien Scrim.

Les anciennes données doivent rester consultables.


==================================================
8. CACHE ET FALLBACK
==================================================

Le site ne doit pas devenir inutilisable si la source distante est temporairement indisponible.

Prévoir :

Online source available
        ↓
Fetch latest data
        ↓
Validate data
        ↓
Update local cache
        ↓
Use latest roster

Si la source est indisponible :

Online source unavailable
        ↓
Use last valid cached roster
        ↓
Website remains functional

Afficher éventuellement :

Using cached hero data

Une erreur de récupération ne doit pas supprimer ou remplacer un roster valide.


==================================================
9. VALIDATION DES DONNÉES
==================================================

Ne remplace pas automatiquement les données existantes par une réponse invalide ou incomplète.

Avant de mettre à jour le roster :

- vérifier que les données sont valides ;
- vérifier qu'il y a bien des héros ;
- vérifier que les IDs sont uniques ;
- vérifier que les images sont accessibles ;
- vérifier que les données correspondent bien à la version Global.

Si la synchronisation échoue, conserver le dernier roster valide.


==================================================

Le système de synchronisation doit explicitement éviter de mélanger les données de :

Honor of Kings Global

et :

王者荣耀 / Honor of Kings CN

Un héros présent uniquement sur CN ne doit pas être ajouté au roster Global simplement parce qu'il existe dans une base de données commune.

La disponibilité Global doit être déterminée à partir de données fiables.

16. MODE BAN & PICK
==================================================

==================================================
18. TIMER DE DRAFT
==================================================

Chaque étape de Ban/Pick doit avoir un timer de :

30 secondes

Le timer doit être clairement visible.

Exemple :

BLUE TEAM — BAN
00:30

Puis :

RED TEAM — BAN
00:30

etc.

Lorsque le timer arrive à zéro :

- l'action correspondante expire ;
- l'utilisateur ne peut plus effectuer l'action ;
- le système passe à l'étape suivante selon le comportement prévu.

Le timer doit être réellement géré par la logique de l'application et pas seulement affiché visuellement.

La phase finale d'attente doit également durer :

30 secondes.

- ban ;

- indisponible ;
- sélection actuelle.

==================================================

DRAFT TIMER

Ces trois timers doivent être complètement indépendants.

==================================================
72. MODES DE JEU — GLOBAL BAN & PICK / FREE FOR ALL
==================================================

Le système de Scrim doit proposer deux modes distincts concernant la disponibilité des héros entre les Games d'une même série.

MODE 1 — GLOBAL BAN & PICK

Ce mode applique une restriction globale sur toute la série.

Lorsqu'une équipe a utilisé un héros comme Pick dans un BO/Game, cette même équipe ne peut plus reprendre ce héros dans les Games/BO suivants de la même série.

Exemple :

Game 1

Team A picks:
Hero X

Game 2

Team A ne peut PAS pick Hero X.

En revanche, l'autre équipe peut utiliser Hero X si les règles de la Draft et les restrictions de cette équipe le permettent.

La restriction est donc :

TEAM-SPECIFIC

et non :

GLOBAL TOUS JOUEURS.

Exemple :

Game 1
Team A → Hero X

Game 2
Team A → Hero X = INTERDIT
Team B → Hero X = AUTORISÉ

Cette restriction doit être appliquée automatiquement par l'interface.

Un héros déjà utilisé par l'équipe dans un Game précédent doit apparaître comme indisponible pour cette équipe dans les Games suivants.

IMPORTANT :

La restriction concerne les PICKS.

Un héros simplement BANNI dans un Game ne doit pas être considéré comme utilisé par l'équipe pour cette règle, sauf si une future règle spécifique le demande.

Les bans restent propres à chaque Draft.

Le système doit conserver un historique des héros déjà pickés par chaque équipe pendant la série.


==================================================
73. MODE FREE FOR ALL
==================================================

Le deuxième mode est :

FREE FOR ALL

Dans ce mode, il n'y a aucune restriction de reprise d'un héros entre les Games d'une même série.

Une équipe peut reprendre un héros autant de fois qu'elle le souhaite dans les Games suivants.

Exemple :

Game 1
Team A → Hero X

Game 2
Team A → Hero X

Game 3
Team A → Hero X

Game 4
Team A → Hero X

Tout cela est autorisé en Free For All.

Les seules restrictions restent celles de la Draft du Game actuellement joué :

- un héros déjà Pick dans la Game actuelle ne peut pas être repris ;
- un héros Banni dans la Game actuelle ne peut pas être Pick ;
- un héros ne peut pas être sélectionné deux fois dans la même Draft.

==================================================
76. FLOWBORN — RÈGLE SPÉCIALE
==================================================

ATTENTION :

Flowborn possède une règle spéciale qui doit être traitée indépendamment de la notion de rôle.

Une équipe ne peut utiliser Flowborn qu'UNE SEULE FOIS pendant toute une série en mode :

GLOBAL BAN & PICK

Cela signifie que dès que Team A a utilisé Flowborn dans un Game :

Team A → Flowborn = définitivement indisponible pour les Games suivants de cette série.

Peu importe le rôle / lane / configuration sous laquelle Flowborn a été utilisé.

Exemple :

Game 1

Team A
Flowborn — Clash Lane

Game 2

Team A
Flowborn — Jungle

INTERDIT.

Autre exemple :

Game 1

Team A
Flowborn — Farm Lane

Game 2

Team A
Flowborn — Roamer

INTERDIT.

Le système doit considérer Flowborn comme un seul héros unique, indépendamment de son rôle.

La règle est :

1 TEAM
+
1 SERIES
+
1 FLOWBORN USE

Une équipe ne peut donc utiliser Flowborn qu'une seule fois dans toute la série.

Cette règle doit être appliquée même si les rôles sont différents.

==================================================

Dans le mode :

FREE FOR ALL

les héros peuvent normalement être repris librement entre les Games.

Cependant, la règle spéciale concernant Flowborn doit être explicitement configurable selon les règles du mode choisi.

Par défaut, appliquer :

FREE FOR ALL
→ Flowborn peut également être repris dans les Games suivants.

GLOBAL BAN & PICK
→ Flowborn ne peut être utilisé qu'une seule fois par équipe sur toute la série.

Ne jamais créer plusieurs entrées de Flowborn simplement parce qu'il peut être associé à plusieurs rôles.

Flowborn doit toujours correspondre à un seul Hero ID.
